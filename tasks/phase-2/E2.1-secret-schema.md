## Goal
The `Secret` record type and its satellite tables — a first-class record with its own holder
set, disclosure state machine, and provenance (D3), attachable to any subject kind. This is
the substrate everything else in Phase 2 (gate, exclusion, overseer) operates on. A secret is
a property of a *relationship* between a fact and its holders, not a field on Entity or Agent.

## Subtasks
- [x] `secret` table: `tenant_id`†, `workspace_id`, polymorphic subject (`subject_kind` ∈
      entity|agent|workspace|knowledge_entry + `subject_id`), `content` (plaintext, routed
      through the `Encryptor` port — identity impl for now), `gist` (one-liner — **the only
      field the disclosure gate will ever see**), `gist_embedding vector(1024)`, `hint_text`,
      **`behavioral_directive`** (the field that makes D4 work — how the agent *acts on* a
      fact without possessing it), `disclosure_state` ∈ undisclosed|hinted|partial|public,
      `scope_key`, `authored_by`, `version`.
- [x] `secret_holder`: `secret_id`, `holder_principal_id`, `holder_kind` ∈
      author|discovered|told, `acquired_at`, `acquired_via_event_id`;
      `UNIQUE(secret_id, holder_principal_id)`.
- [x] `secret_disclosure_event` ‡ (append-only, no UPDATE/DELETE grant): `secret_id`,
      `session_id`, `event_seq`, `disclosed_by_principal_id`, `disclosed_to` JSONB, `mode` ∈
      full|hint|inferred|leaked, `decision_id`, `message_id`.
- [x] `disclosure_decision` ‡ (append-only): `session_id`, `event_seq`, `agent_id`,
      `behavior_profile_version`, `decisions` JSONB (`[{secret_id, action, rationale,
      confidence}]`), `model_profile_id`, `latency_ms`, `token_usage` JSONB. The gate's
      recorded rationale is **evidence** (Q11 owns its retention question — Phase 5, Legal).
- [x] RLS with `FORCE` on all four tables, policy shape per CLAUDE.md rule 4; isolation
      negative tests (cross-tenant + filter-omission; library-matrix not applicable, see
      note above) added to `tests/isolation/` in this PR, plus registered in the shared
      `test_coverage_guard.py`/`test_append_only_grants.py` registries.
- [x] Repo module `core/secrets/repo.py` — importable **only** by `core/assembler/` and
      `core/overseer/` (INV-1); already named in the `tests/architecture/` lint config
      (T0.5) — verified passing, no config change needed.
- [x] **Facilitator default:** the facilitator does *not* see held secrets (brief item 14).
      Visibility opt-in is an explicit scope configuration, never a default — no facilitator
      holder row is ever created implicitly anywhere in this schema or its repo.

## Acceptance criteria
- A secret attaches to an entity, an agent, a workspace, and a knowledge entry through the
  same polymorphic subject columns — no per-kind table variants.
  → `test_secret_attaches_to_all_four_subject_kinds`
- Cross-tenant reads on all four tables return zero rows with the ORM filter deliberately
  omitted (RLS, not discipline).
  → `test_secret_tables_cross_tenant_filter_omission_returns_zero_rows`
- The app DB role cannot UPDATE or DELETE `secret_disclosure_event` or
  `disclosure_decision` — asserted as grants, not convention.
  → `test_disclosure_tables_reject_update_and_delete_as_app_role`
- No module outside `core/assembler/` and `core/overseer/` imports `core/secrets/repo` —
  the INV-1 lint fails a deliberately-planted violation.
  → `test_import_lint_rejects_secrets_repo_import_from_outside_the_allowlist`

## Design decisions
- **A record, not a field (D3).** Two conspirators share one secret (one row, two holders);
  disclosure is a state machine, not a boolean; provenance and audit hang off the record.
  Enterprise mapping (MNPI, deal-team confidentiality) and swdev mapping (embargoed
  vulnerability/incident details) fall out for free — same table, different overlay label.
- **`behavioral_directive` is not optional in spirit.** It is the field most likely to be
  omitted by authors and the one that makes exclusion (E2.6) produce an agent with a
  motivation instead of a lobotomy. The column is nullable; E2.2's authoring flow treats an
  empty directive as a lint warning, not a silent default.
- **Credentials are not secrets.** Tool/provider credentials stay `credential_ref`s into a
  secret manager (CLAUDE.md); a `Secret` row holds narrative/world facts only. The swdev
  overlay's "Embargoed Info" label covers vulns/incidents/plans — never API keys.
