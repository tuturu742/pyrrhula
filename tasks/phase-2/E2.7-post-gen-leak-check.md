# E2.7 — Post-generation leak check

**Phase:** 2 · **Track:** E · **Est:** 3d · **Status:** done
**Depends on:** E2.6 (done) · **Blocks:** —
**Plan refs:** §8.4 step 5, §16.4 (Q4 does *not* apply here)

## Goal
Defence in depth behind exclusion: after generation, compare the reply against every
*concealed* secret's plaintext (fuzzy match + embedding similarity). On a hit: regenerate
once; still hot → replace with a safe fallback reply and alert the overseer. This catches
what exclusion cannot: hint drift, a model inferring the fact from a too-specific directive,
an author writing a directive that gives the game away.

## Subtasks
- [x] `core/secrets/leak_check.py`: fuzzy match (normalized token overlap, same n-gram
      shape as E2.2's plaintext-leak detector) + `cos_sim(reply_embedding,
      secret_content_embedding) > τ_leak` against each concealed secret of the speaking
      agent this turn. Embeddings via the existing embedding service (A1.3) port,
      `purpose='embed'` (the port's own default).
- [x] Regenerate-once path: same context, regeneration flagged; second hit → safe fallback
      reply (bland in-voice deflection; a pack-provided template is a future
      customization point — no pack/template registry exists yet to hook into, so this
      ships one fixed deflection string) + overseer alert (`session_event`, kind
      `secret_leak_alert`; Director's View surfacing is E2.11's job, not this task's).
- [x] Every check outcome (clean / regenerated / fallback) is the function's own typed
      return value (`PostGenerationOutcome`) — recording it onto the message row itself
      is the live-wiring step this task defers (see note above), same shape as
      `core.resolution.contradiction`'s `moderation_flags` write it will eventually join.
- [x] Wire into `tests/leak/` as the runtime complement of E2.6's payload assertions.
- [x] **Q4's badge decision explicitly does not apply**: contradicted *narration* gets a
      badge and no regen (C1.7); a *leak* regenerates then falls back. Documented the
      asymmetry in the module docstring — the loss profiles differ (style bug vs
      irreversible disclosure).

## Acceptance criteria
- A reply containing a paraphrase of a concealed secret above τ_leak triggers exactly one
  regeneration; a second hot reply yields the fallback and an overseer alert, never a third
  generation.
  → `test_leak_flag_regenerates_once_then_falls_back_with_overseer_alert`
- A clean reply passes with no extra model calls beyond the embedding.
  → `test_clean_reply_incurs_no_regeneration`
- The check runs only against secrets concealed *this turn* for *this agent* — revealed and
  public secrets are not flagged.
  → `test_revealed_secrets_are_not_flagged_by_the_leak_check`

## Design decisions
- **This is a tripwire, not the wall.** Exclusion (E2.6) is the control;
  `unauthorized_disclosure_rate == 0` must hold from exclusion alone (the E2.8 gate treats a
  nonzero value as a P0 assembler bug, not something this check papers over). The check
  exists for the failure modes exclusion structurally can't see.
- **τ_leak tuned against E2.8's corpus**, not intuition — too low and every mention of the
  north road is a "leak"; too high and paraphrases walk through.
