## Goal
The overseer console: secrets grouped by holder, the disclosure timeline, and "what does
agent X believe now" — everything served by `OverseerService.inspect()`, with a persistent
"your inspections are logged" indicator. The label is overlay-resolved: Director (RPG),
Compliance Reviewer (enterprise), Engineering Director (swdev).

## Acceptance criteria
- Expanding a secret's plaintext produces exactly one new audit row per expansion,
  observable in the UI's own inspection counter.
  → `test_each_plaintext_expansion_writes_exactly_one_audit_row`
- A principal without `secret:inspect` receives no gists, no counts, no timeline — the API
  returns a permission error, not an empty list (absence of data is itself information).
  → `test_non_overseer_gets_permission_error_not_empty_lists`
- The audit indicator is present on every director-view route (component test walks the
  route tree).
  → `test_audit_indicator_present_on_all_director_view_routes`

## Design decisions
- **Gist-by-default, plaintext-on-click** keeps the audit log meaningful: a page that
  auto-loads fifty plaintexts writes fifty rows of noise and trains reviewers to ignore the
  log. Deliberate expansions make each row an intention.
