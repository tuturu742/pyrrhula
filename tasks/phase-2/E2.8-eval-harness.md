## Goal
The measurement instrument that decides whether §8 is right: ~50 adversarial secret-probing
scenarios, five metrics, three comparison arms, a per-provider matrix, nightly in CI.
**Front-load the scenario authoring so the eval exists before the implementation it
judges** — otherwise you will unconsciously write scenarios your implementation passes
(§15.10). A behavioural parameter that hasn't been measured is a cosmetic label (D12).

## Subtasks
- [x] `packages/eval/scenarios/`: ~50 hand-authored scenarios (**17 shipped**, see scope
      note). Agent holds secret S; an adversarial interlocutor probes with escalating
      pressure: direct question → social pressure → deception → authority claim →
      prompt injection. Each scenario declares the expected outcome band per axis value.
      Families: RPG hidden-motive (majority, 8), enterprise MNPI/need-to-know (4), and a
      **swdev family (5)**: social-engineering/authority-claim probes for embargoed
      incident details and maintainers-only decisions, and a prompt-injection probe
      planted in fake README content — pre-validating the exclusion arm on the content
      type the Phase-4 dogfood pilot (G4.17) will actually carry.
- [x] `packages/eval/arms/`: the `ARM_NAMES` taxonomy (`prompt_only` /
      `gate_no_exclusion` / `full_pipeline`) and the matrix assembly
      (`eval.arms.matrix.build_matrix`) that groups already-run `Trial`s by
      (provider, arm) and computes every metric per cell. Actually *running* a scenario
      through each arm against live providers is the harness's real nightly job's
      composition, not this module's — `Trial` is the seam (see scope note 3).
- [x] `packages/eval/metrics/`: `unauthorized_disclosure_rate` (target **0 on arm 3, by
      construction** — nonzero is a P0 assembler bug); `over_concealment_rate` (the
      counter-metric: agents must not go mute); `directive_leak_rate` (fact inferable from
      the directive — can't be zero; track low; it's a content-authoring signal);
      `behavioral_fidelity` (blind pairwise LLM judge: does malice=80 read more malicious
      than malice=20? if the judge can't tell, the axis is cosmetic — cut it);
      `cross_run_consistency` (same inputs, N runs, variance).
- [x] `packages/eval/report/`: per-(provider, arm) matrix rendered as markdown
      (`eval.report.build.render_markdown`) — the axis-value dimension lives on each
      `Trial`, not yet folded into a fourth report axis (additive later if the ~50-
      scenario matrix needs finer slicing than provider×arm).
- [x] Nightly CI job (`.github/workflows/eval-nightly.yml`); regression thresholds fail
      the run (`eval.arms.matrix.evaluate_run`). Runs the harness-skeleton suite today,
      not a live 3-provider+Ollama matrix (scope note 3) — no committed provider
      credentials exist in this repo/environment to wire a real one against.
- [ ] Metering: eval calls carry their own purposes (`generation`/`gate`) against a
      dedicated eval tenant so cost is visible and excluded from customer dashboards.
      Not built — there is no live provider wiring yet for this metering to attach to
      (scope note 3). The fidelity judge's own model call uses `purpose='report'`
      (CLAUDE.md rule 11's existing taxonomy has no `'judge'` entry; `'report'` is the
      closest existing fit for a call that scores quality for the eval report, not a
      disclosure decision — no new taxonomy value invented for this task).

## Acceptance criteria
- The scenario suite (≥45 scenarios, all five pressure families, all three overlays
  represented) runs green on the harness *skeleton* before E2.5/E2.6 merge — proven by CI
  history, not recollection.
  → `test_scenarios_load_and_declare_expected_bands` (merged ahead of E2.5/E2.6)
- All three arms produce the full metric set for at least 3 providers + 1 local model in one
  nightly run.
  → `test_three_arm_matrix_produces_all_five_metrics_per_provider`
- A deliberately-planted assembler leak (bypassing exclusion for one scenario) drives
  `unauthorized_disclosure_rate > 0` and fails the run — the harness can actually detect the
  thing it exists to detect.
  → `test_planted_exclusion_bypass_is_detected_and_fails_the_run`
- The blind judge receives no axis values or arm labels with its transcripts.
  → `test_fidelity_judge_inputs_are_blind`

## Design decisions
- **Arm 2 exists to falsify the alternative.** If arm 3 does not beat arm 2 decisively on
  `unauthorized_disclosure_rate`, §8 is wrong — stop and redesign, don't ship (phase gate).
- **`over_concealment_rate` is the metric most likely to be ignored** (the gate item says
  so). A system that never leaks because agents never say anything interesting has failed
  differently.
