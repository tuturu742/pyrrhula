## Goal
The structured pre-decision that chooses conceal / hint / reveal per secret before
generation: a cheap should-fire prefilter, then one schema-validated call on a small model
that sees **gists only, never `secret.content`**, persisted as a `DisclosureDecision`.
On any failure — timeout, malformed output, provider error — the gate **fails closed to
conceal**. The gate decides; E2.6 enforces. Neither is useful without the other.

## Subtasks
- [x] **Should-fire prefilter** (no model call, §8.5): fire iff
      `(agent's held secrets ∩ active scope ≠ ∅) AND ("mechanical" ∉ phase.flags) AND
      (max cos_sim(recent-turns embedding, secret.gist_embedding) > τ)`. τ set **low** and
      configurable — a false fire costs a cent; a false skip costs the plot. Not-fired ⇒
      all secrets default to conceal (safe path, no decision row needed beyond a marker).
      The "held ∩ active scope" intersection is the caller's job (needs `secrets.repo`
      reads this module can't perform) — `compute_fired_secrets` takes the already-
      intersected candidate list.
- [x] **Gate call**: one batched structured call per agent-turn covering all fired secrets.
      Input: persona summary, `[{secret_id, gist}]`, relevant axis values
      (`secret_disclosure_propensity`, `deception_propensity`, …), phase, recent turns,
      addressed-by, pressure signals. Output: strict JSON schema
      `{decisions: [{secret_id, action ∈ conceal|hint|reveal_full, rationale, confidence}],
      posture}`. Budget ~200–400 tokens in, ~150 out.
- [x] Strict schema validation; on local models use grammar-constrained decoding (Ollama
      JSON-schema format / GBNF) — Q5's all-modes decision makes this mandatory, not nice.
      Grammar wiring itself is an adapter-level concern (`ModelProvider.
      generate_structured`); this task owns the schema and the business-rule validation
      on top of it (secret_id set must match the fired batch exactly, action must be a
      legal value).
- [x] **Fail-closed**: validation failure, timeout, or provider error ⇒ every fired secret
      is concealed and the failure is recorded on the decision row. A concealed agent is
      flat; a failed-open agent is compromised.
- [x] Persist `DisclosureDecision` (E2.1's table) with model profile, latency, token usage;
      metered `purpose='gate'` in the same transaction (rule 11). D14 note: `gate` may be
      cloud-permitted even in hybrid mode because it sees gists only.
- [x] Batch semantics: one call for all of an agent's fired secrets, not one per secret.

## Acceptance criteria
- With the prefilter not firing, no model call is made and every held secret is concealed.
  → `test_unfired_prefilter_conceals_all_without_a_model_call`
- A gate response failing schema validation results in conceal-all, a recorded failure, and
  no exception escaping to the turn loop.
  → `test_malformed_gate_output_fails_closed_to_conceal`
- The gate call's request payload contains gists and never `secret.content` — asserted by
  inspecting the actual provider-bound payload for a planted plaintext marker.
  → `test_gate_payload_contains_gists_and_never_plaintext`
- Every gate decision persists as a `DisclosureDecision` with `purpose='gate'` usage in the
  same transaction.
  → `test_gate_decision_and_usage_record_commit_atomically`

## Design decisions
- **Gists-only is a security boundary, not an optimisation.** It is what lets the gate run
  on a small/cheap/possibly-cloud model under D14 without the secret leaving the building.
- **The gate caps disclosure, not inference** (§8.4's honest limit): a player can still
  *deduce* the fact. Turn-granularity is acceptable in a turn-based engine.
- **Asymmetric τ.** Over-firing burns pennies; under-firing silently converts "reveal at the
  dramatic moment" into "never reveal". Tune with E2.8's `over_concealment_rate`, not by
  feel.
