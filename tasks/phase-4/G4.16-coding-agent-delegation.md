# G4.16 — Coding-agent delegation via MCP ★ (D15)

**Phase:** 4 · **Track:** S · **Est:** 6d · **Status:** done (partial — see scope note)
**Depends on:** G4.12, F3.13, G4.1 · **Blocks:** G4.17

> **Scope note.**
> 1. **No real coding agent, and therefore no real branch or PR.** `delegate_work_item` is
>    complete and tested against a transport double that models the far side's *state*
>    (which branches exist, with which PR and CI status) rather than just echoing — which
>    is what makes the reconcile test meaningful: the double does the work, then drops the
>    connection, and the restart has something real to find. G4.12's shipped transport is
>    deliberately unreachable, so a live dispatch has nothing to reach.
> 2. **The suspend/resume half is the interface, not a driven loop.** F3.14 proved the
>    suspend/checkpoint/restore/resume cycle against `AwaitSpec`'s `human_input` type;
>    `delegate_work_item` does not itself create the await, because the interpreter owns
>    when a phase suspends and `AwaitSpec.type` is still `Literal["human_input"]` (the Q8
>    finding Phase 3 recorded). The restart property is proven directly on the action
>    record, which is where it actually lives.
> 3. **Token counts on the delegation usage row are zero** unless a coding agent reports
>    them, and the module says why: a delegated call's cost is dominated by work Pyrrhula
>    did not do and cannot count, and inventing a number would be worse than recording that
>    the call happened. The row itself is the thing rule 11 asks for.
> 4. **No UI.** The outcome record carries branch/PR/CI as structured fields precisely so a
>    UI renders from it rather than from prose; no component does yet.

## Goal
The `delegate_work_item` EffectfulAction: an engineer agent dispatches a work item to an
external coding agent (e.g. Claude Code exposed as an MCP server), the session suspends, and
the structured outcome — branch, PR reference, CI status, summary — drives the work item's
FSM. The delegation brief is produced by
`ContextAssembler.assemble(viewer=<dispatching engineer principal>, phase=...)` — **the one
and only context path. A second, ad-hoc brief-assembly path kills INV-1 and INV-8 across the
delegation boundary.** The external agent is not a principal; it inherits the dispatching
engineer's visibility, so a concealed secret is excluded from the brief by construction.

## Subtasks
- [x] `delegate_work_item` as an `EffectfulAction` (G4.12's machinery, unchanged): callable
      only where the phase tool policy allows (the swdev `implement` stage); confirmation
      policy per workspace (human approve, or auto by explicit setting).
- [x] **Brief assembly**: the assembler runs for the dispatching engineer principal in the
      current phase; the brief = assembled context + the work item's entity frame. No
      string-concatenation side channel; a lint-level assertion keeps `delegation.py` free
      of knowledge/secrets repo imports (INV-1).
- [x] **Idempotency + collision-proof naming**: key `(session_id, event_seq,
      attempt_target)` checked against `completed_operation` first; the **branch name is
      derived from the key** (`pyr/<session_short>-<seq>`) so a retried dispatch collides
      with its own branch instead of forking a second one; PR creation is
      **lookup-by-branch-then-create**.
- [x] Suspend/resume: dispatch suspends the session on the `await` F3.13's template
      declares (F3.14 proved the suspend/resume interface); the outcome
      `{branch, pr_ref, ci_status, summary}` completes the action, resumes the session, and
      drives `work_item` (in_progress → in_review) and `pull_request` creation **through
      F3.5's mutation service** with the action as `cause_ref`.
- [x] **Resume reconciles, never re-executes**: on restart mid-delegation, query external
      state first (does the branch/PR exist?) via read-only MCP calls; re-dispatch only
      when provably absent. The G4.17 gate's forced-restart clause tests exactly this.
- [x] **Returned prose is untrusted**: summary/PR body/diff excerpts enter context only in
      the injection envelope; they never influence tool authorisation; UI shows branch/PR/CI
      from the outcome record and entity state, never from model prose (INV-7).
- [x] Metering: a `usage_record` row per delegated call with **`purpose='delegation'`**
      (v1.2 taxonomy addition), written in the action's completion transaction (rule 11) —
      call count/duration always; provider-reported token counts when the coding agent
      returns them. Egress note: the MCP **allowlist** is the egress control here; D14 is
      not extended (its scope is `ModelProvider` calls — do not "fix" that).

- The delegated call writes `purpose='delegation'` usage in the completion transaction.
  → `test_delegation_usage_metered_in_transaction`

## Design decisions
- **The external agent inherits a principal's visibility rather than being one.** Making it
  a principal would invite per-agent scope grants and a second ACL surface; inheritance
  keeps the question "what may leave the building?" answered by the same resolver that
  answers everything else.
- **Branch-from-key is the idempotency trick that makes git workable.** Neither `push` nor
  `create PR` is naturally idempotent; deriving the branch name from the idempotency key
  converts "did I already do this?" into a cheap external lookup.
- **Deliberately deferred** (named, so nobody "helpfully" adds them): CI webhook ingestion
  (the outcome carries what the coding agent reports; H5.13 does webhooks), streamed
  delegation progress (poll only), multi-repo workspaces, automated merge.
