# G4.7 — Export modes + leak test ★

**Phase:** 4 · **Track:** G · **Est:** 3d · **Status:** done
**Depends on:** G4.5 · **Blocks:** —
**Plan refs:** §11.4, §15.7

## Goal
The three export modes — participant / full / sanitised — with the choice unmissable in the
UI, an audit row on every full export, and the CI leak test: a sanitised bundle **provably
contains no held secret plaintext**. This is the export-side counterpart of INV-8.

## Subtasks
- [x] Mode semantics on `ExportService`: **participant** (any participant; secrets only if
      they hold them — their normal visibility, `phase=EXPORT`); **full** (requires
      `secret:inspect`; everything; writes an `audit_log` row as loudly as inspecting a
      secret — same chain); **sanitised** (any principal; zero secret content in any file;
      redaction stubs in `manifest.redactions[]`).
- [x] UI: the mode choice is a required, explicit step with per-mode consequences stated;
      no default silently selected.
- [x] `tests/leak/` CI test: build a workspace with held secrets (content, gists, hints,
      directives), run a sanitised export, and scan **every byte of every file in the
      bundle** for exact, fuzzy, and embedding-level matches of each secret's plaintext —
      including inside session events, manifests, and summaries.
- [x] Same scan (scoped to unheld secrets) for participant mode: a participant bundle must
      not contain plaintext of secrets they don't hold.

## Acceptance criteria
- A sanitised bundle contains no match (exact/fuzzy/embedding) of any held secret's
  plaintext anywhere in the archive.
  → `test_sanitised_bundle_contains_no_held_secret_plaintext`
- A participant bundle contains plaintext only of secrets that participant holds.
  → `test_participant_bundle_limited_to_held_secrets`
- Every full export writes a chained audit row naming the exporter; the verifier detects a
  tampered one.
  → `test_full_export_writes_verifiable_audit_row`
- A principal without `secret:inspect` requesting a full export is refused before any object
  selection begins.
  → `test_full_export_requires_inspect_permission`

> **Note on the participant rule.** "secrets only if they hold them" is *holder*-scoped,
> not author-scoped. E2.1's `SecretView` keys its plaintext on authorship, which answers a
> different question, so `_add_secrets` reads `secret_holder` directly (via
> `secrets.authoring.list_holders` — a freely-importable sibling, so INV-1 holds). An
> author who does not hold their own secret gets no plaintext in participant mode, and
> `test_participant_bundle_limited_to_held_secrets` asserts exactly that.

## Design decisions
- **The leak test scans the artifact, not the code path.** The property customers rely on
  is about the bytes in the ZIP; asserting it at the artifact level catches every future
  serializer someone bolts on.
