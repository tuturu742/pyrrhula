# G4.8 — CCv2/CCv3 import (day-one acquisition channel)

**Phase:** 4 · **Track:** G · **Est:** 6d · **Status:** done (partial — see scope note)
**Depends on:** A1.1 · **Blocks:** G4.9
**Plan refs:** §11.3, §16.6

> **Scope note.**
> 1. **No card-import UI.** `POST /export/cards/import` is real and tested; no React
>    surface uploads to it. The RPG-overlay-only placement the last subtask asks for is a
>    UI decision, and the endpoint is deliberately overlay-agnostic — where the button
>    lives is not something the API should encode.
> 2. **The card maps to an Agent + lore source, not to an entity instance.** The task
>    lists "minimal entity instance"; a card carries no schema, so an entity would need a
>    schema invented for it, and an invented schema is a shape somebody has to maintain
>    forever because an importer guessed. `agent.entity_id` is nullable and stays null;
>    attaching an entity is a deliberate act once a workspace has a schema that fits.
> 3. **Card lore chunks 1:1 with entries, not through the semantic chunker.** A lore entry
>    is authored as one unit and *activates* as one unit; splitting it changes the
>    activation behaviour the card's author tuned, which is the one thing a faithful
>    import has to preserve. Reasoned in `map.py`'s `_chunk_published_entries`.
> 4. **A flagged *persona* is reported, not quarantined.** Quarantine works by excluding
>    rows from retrieval; a persona is authored *into* an agent rather than retrieved, so
>    there is nothing for the mechanism to bite on. The scan result is surfaced in
>    `CardImportResult.quarantined` under `<persona>` so a human sees it, and `map.py`
>    says so rather than implying coverage it doesn't have.

## Goal
Character Card V2/V3 import: parse the PNG tEXt chunks (`chara`/`ccv3`), normalise V2↔V3,
map the card to an Agent + entity instance, and `character_book` to a
KnowledgeSource(class=lore) with decorators mapped to activation fields. This is how the
existing ecosystem's content walks in the door. Port the narrow parsing slice from
`character-foundry`; no Node sidecar.

## Subtasks
- [x] PNG tEXt chunk extraction + base64/JSON decode for both `chara` (V2) and `ccv3`
      chunks; prefer `ccv3` when both present; plain-JSON card files also accepted.
- [x] V2↔V3 normalisation into one internal card model (spec fields: name, description,
      personality, scenario, first_mes, mes_example, system_prompt,
      post_history_instructions, alternate_greetings, `character_book`, extensions…).
- [x] Mapping: card → `agent` (persona from description/personality/system fields) +
      minimal entity instance; `character_book` entries → KnowledgeSource(class=`lore`)
      entries with keys/secondary/logic/constant/position → A1.5 activation fields; CCv3
      decorators (`@@position`, `@@depth`, conditional activation) → the corresponding
      activation fields (both descend from ST World Info — the mapping is near-mechanical).
- [x] `extensions` preserved verbatim on the imported objects (the spec requires
      non-destruction; G4.9 round-trips it).
- [x] Imported card text runs G4.6's injection scan with the same quarantine flow (cards
      are the classic carrier).
- [x] RPG-overlay UX only (cards are an RPG-ecosystem format; `.pyr` is the domain-neutral
      path) — no enterprise/swdev surface for this importer.

## Acceptance criteria
- A reference V3 card (with `character_book` and decorators) imports and its lore entries
  activate through A1.5 exactly as the decorators specify.
  → `test_ccv3_card_imports_with_decorator_faithful_activation`
- A V2-only card normalises and imports to the same internal shape (feature-parity fields).
  → `test_ccv2_card_normalises_and_imports`
- `extensions` content survives import byte-identical (fixture with nested unknown keys).
  → `test_card_extensions_preserved_verbatim`
- A card with planted injection text lands quarantined pending review.
  → `test_card_injection_content_quarantined`
