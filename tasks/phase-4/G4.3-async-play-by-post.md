> **Scope note.**
> 1. **The shipped `Notifier` adapter logs; it does not send email.** The pipeline — who
>    is notified, exactly once, with what visibility-filtered content — is complete and
>    tested behind `core/ports/notifier.py`, and swapping the channel is a one-line
>    change in `worker/notifier_factory.py`. This environment has no mail server, SMTP
>    credentials, or webhook endpoint, so an "email adapter" here would be untested code
>    asserting nothing. A log line is also the right production default for a self-hosted
>    deployment that hasn't configured mail: it fails visibly rather than silently
>    swallowing "it's your turn". Same discipline as E2.8's eval harness.
> 2. **No periodic scheduler enqueues digests.** `send_digest` and its worker handler are
>    real and tested; nothing yet decides *when* daily is. `window_key` is a job-payload
>    parameter precisely so periodicity stays a scheduling decision — the cron/beat
>    surface that would set it is deployment infrastructure no Phase-4 task owns.
> 3. Resume-into-context **is** wired: `POST /sessions/{id}/recap` enqueues G4.1's
>    summariser for the calling principal, closing the gap G4.1's own scope note named.

## Goal
Sessions that span days: B1.6's `await`/timeout primitive grows notifications, digest
emails, and per-actor pacing. A play-by-post game and an enterprise review cycle spanning a
week are the same mechanism — an `await_state` with a long timeout and humans who need to be
told it's their turn.

## Subtasks
- [x] Notification pipeline: `await_state` creation for a human actor enqueues a
      notification job (**the shipped channel is a log adapter, not email — see scope
      note**; the channel is an adapter, not a core concern);
      `timeout_at` approach triggers reminder policy per workspace settings.
- [x] Digest emails: a worker job batches per-principal pending awaits + recent visible
      events into a digest (**periodicity not scheduled — see scope note**) — the event selection runs through visibility filtering
      for that principal (a digest is a small report; the G4.10 rule applies).
- [x] Per-actor pacing: workspace/process-level pacing config (e.g. "each actor has 48h,
      reminder at 24h, `on_timeout` transition after") — data on the ProcessDefinition,
      interpreted by B1.6's timeout job, no new engine semantics.
- [x] Resume-into-context: a human acting on a digest link lands in the session view with
      G4.1's summary path serving "what happened since your last turn".

## Acceptance criteria
- A human-turn `await` sends exactly one notification, one reminder at the configured
  fraction, and fires `on_timeout` at expiry — idempotent under worker retries.
  → `test_await_notification_reminder_and_timeout_fire_once_each`
- Digest content for a principal never includes events outside their visibility (planted
  hidden-scope event stays absent).
  → `test_digest_is_visibility_filtered_per_recipient`
- A session with a week-long await survives a full restart between notification and
  response (durable `await_state`, B1.6) and resumes correctly on reply.
  → `test_long_await_survives_restart_and_resumes_on_reply`
