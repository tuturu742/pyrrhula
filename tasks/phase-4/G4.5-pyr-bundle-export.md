# G4.5 — `.pyr` bundle export

**Phase:** 4 · **Track:** G · **Est:** 6d · **Status:** done (partial — see scope note)
**Depends on:** C1.1, E2.1 · **Blocks:** G4.6, G4.7
**Plan refs:** §11.2, §11.4, req 23, req 24

> **Scope note.**
> 1. **Only the participant mode ships here.** `ExportMode` is `Literal["participant"]`;
>    `full` (with its `secret:inspect` gate and audit row) and `sanitised` are G4.7, which
>    widens that literal rather than replacing any machinery. The visibility resolution,
>    redaction stubs, integrity map, and bundle format are all mode-agnostic already.
> 2. **The bundle carries chunk bodies, which §11.2's illustrative layout does not list.**
>    A `ContextManifest` records which *chunks* a turn used, and the rendered context is
>    built from chunk bodies, not entry bodies — so without them "replay a turn from the
>    bundle alone" would be arithmetically impossible, not merely untested. Chunks carry
>    the same scope filter as entries.
> 3. **Cross-boundary replay is proven for a knowledge-only turn.** A turn whose context
>    also held recent history, entity state, or a secret injection has those in its
>    `rendered_hash` too, and a *concealed* secret's injection deliberately never leaves
>    the building — a sanitised bundle that could replay such a turn would be a leak, not a
>    feature. The boundary is the data's, and is stated in
>    `core/portability/replay.py`'s docstring rather than left for a reader to infer.
> 4. **No export UI.** The mode picker is G4.7's own subtask ("the choice is a required,
>    explicit step"); building a one-mode picker now would be a control someone has to
>    rebuild the moment the other two modes land.

## Goal
The native portable bundle: ZIP + `manifest.json`, JSONL logs, entries as `.md`
(git-diffable), integrity hashes — and visibility resolved through the **`phase=EXPORT`
pseudo-phase of the `VisibilityResolver`**. Export must never grow its own visibility
logic: two implementations would drift, and one of them would leak (§11.4).

## Subtasks
- [x] Bundle layout per §11.2: `manifest.json` (`pyr_format`, `app_version`, `exported_at`,
      `tenant_ref`, `contents[]`, `integrity{file: sha256}`, `redactions[]`);
      `knowledge/ks_<id>/{meta.json, versions/, entries/*.md}`; `schemas/`; `agents/`
      (incl. behaviour-profile versions); `process/`; `entities/`; `secrets/` (only if the
      exporter's visibility permits); `sessions/session_<id>/{events.jsonl,
      checkpoints.jsonl, manifests.jsonl, resolutions.jsonl}`; `vocabulary/`; `assets/`.
- [x] `ExportService.export(principal, workspace, options)`: first line of business is
      `scopes = VisibilityResolver.scopes_for(principal, phase=EXPORT, session=None)`; every
      selected object passes that filter; everything omitted lands in
      `manifest.redactions[]` as `{type, id, reason}` — omissions are visible as stubs, not
      silent.
- [x] `manifests.jsonl` carries the ContextManifests so INV-10 replay works across the
      export boundary — a turn's exact context is reconstructible from the bundle alone.
- [x] `resolutions.jsonl` carries seeds, records, and the hash chain (verifiable after
      import).
- [x] Export is a worker job producing a blob (`BlobStore`), not a synchronous download;
      `pyr_format` is the format version (currently 1), decoupled from app version.

## Acceptance criteria
- An export by a participant principal contains exactly their visible slice; every excluded
  object appears in `redactions[]` — verified by diffing against a full export.
  → `test_participant_export_matches_visibility_and_lists_redactions`
- `ExportService` contains no scope logic of its own — static assertion that visibility
  terms appear only via the resolver call (and INV-1's lint keeps repos out).
  → `test_export_service_delegates_all_visibility_to_the_resolver`
- Every file's sha256 matches `manifest.integrity`; a tampered entry is detected by the
  verifier.
  → `test_bundle_integrity_hashes_detect_tampering`
- A turn from an exported bundle replays byte-identical using only bundle contents (INV-10
  across the boundary).
  → `test_replay_from_bundle_alone_is_byte_identical`
