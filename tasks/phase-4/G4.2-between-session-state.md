> **Scope note.** The overseer/authoring **UI** for the change feed is not built: the
> `GET /workspaces/{id}/changes` endpoint is real, permission- and scope-filtered, and
> covered by `packages/api/tests/test_between_session_flow.py`, but no React surface

> the two are reconciled. Named here rather than left as a silent gap.

## Goal
Workspace state persists and evolves outside sessions: a workspace clock, scheduled entity
effects, and out-of-session state changes — time passing between game nights, a ticket aging
between review cycles, a work item unblocked while nobody was in a session.

## Subtasks
- [x] Workspace clock: an explicit, owner-advanced timeline value on the workspace (not
      wall-clock — fictional/process time and real time are different things; the clock
      advances by deliberate action or scheduled job, never implicitly on read).
- [x] Scheduled entity effects: declarative schedule entries (`at clock >= X` or `every N`)
      that apply F3.5 mutations via the worker with `cause='fsm'`/`cause_ref` to the
      schedule; idempotent per (schedule, tick).
- [x] Out-of-session mutation surface: the F3.5 service invoked with `session_id = NULL` —
      human edits and scheduled effects both land in `entity_state_change` with full
      provenance; "what changed since last session" is a query over the change log, and
      G4.1's summariser consumes it on next resume.
- [x] Overseer/authoring UI: a between-sessions change feed on the workspace (change rows,
      not prose). → **API only** (`GET /workspaces/{id}/changes`); no React surface — see
      scope note.

## Acceptance criteria
- Advancing the clock past a scheduled effect applies it exactly once (idempotent under
  worker retry), visible in `entity_state_change` with schedule provenance.
  → `test_scheduled_effect_applies_exactly_once_per_tick`
- Out-of-session changes appear in the next session's G4.1 summary as record-injected facts.
  → `test_between_session_changes_surface_in_next_resume_summary`
- The clock never advances as a side effect of reads or session starts (explicit action
  only).
  → `test_workspace_clock_only_advances_explicitly`
