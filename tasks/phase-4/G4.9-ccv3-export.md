# G4.9 — CCv3 export (lossy)

**Phase:** 4 · **Track:** G · **Est:** 3d · **Status:** done (partial — see scope note)
**Depends on:** G4.8 · **Blocks:** —
**Plan refs:** §11.3

> **Scope note.** **The caller supplies the PNG the card is written into.** Pyrrhula does
> not generate portrait art and deliberately does not ship a placeholder: a card's image
> belongs to its author, and a default would put a Pyrrhula-branded square on every card
> anyone exports. `POST /export/cards/{agent_id}` takes the image as an upload and writes
> both chunks into it; the loss report is its own `GET .../preview` endpoint so the user
> sees it *before* choosing to download, which is what §11.3 asks for and what a report
> delivered alongside the file could not deliver.

## Goal
Best-effort CCv3 export with honest loss accounting: write both `chara` and `ccv3` chunks
(SillyTavern compatibility), put Pyrrhula-native data into `extensions` (the spec reserves
it and requires implementations not to destroy it), and show an **explicit loss report
before download** — no CCv3 field exists for behaviour profiles, secrets, or process
definitions, and pretending otherwise would be a silent lie.

## Subtasks
- [x] Agent + lore → card mapping (inverse of G4.8's, shared model); lore entries →
      `character_book` with activation fields mapped back to keys/decorators where
      expressible.
- [x] Native data → `extensions.pyrrhula` (behaviour-profile reference, activation fields
      with no CCv3 equivalent, schema references); a re-import through G4.8 restores what
      the extension carries.
- [x] Write both PNG chunks; a card exported here re-imports into SillyTavern-compatible
      tooling (chunk-shape fixture check).
- [x] **Loss report**: before download, an itemised list of what the card cannot carry
      (secrets: never exported here at all; process: not representable; per-phase budgets:
      dropped …) — rendered, and embedded in `extensions.pyrrhula.loss_report` for the
      record.
- [x] Secrets are excluded unconditionally — card export is not an export *mode* (G4.7);
      it is always sanitised-equivalent for secret content.

## Acceptance criteria
- Export → re-import (Pyrrhula) round-trips everything the extension carries; the loss
  report exactly names what didn't survive.
  → `test_card_roundtrip_restores_extension_carried_data_and_loss_report_is_accurate`
- The exported PNG carries both chunks with spec-valid payloads.
  → `test_exported_card_has_valid_chara_and_ccv3_chunks`
- No secret content (any of the four fields) appears anywhere in an exported card —
  `tests/leak/` scan, same method as G4.7.
  → `test_exported_card_contains_no_secret_content`
