# G4.10 — Report pipeline (req 25)

**Phase:** 4 · **Track:** G · **Est:** 6d · **Status:** done (partial — see scope note)
**Depends on:** C1.3 · **Blocks:** G4.11, H5.10
**Plan refs:** §11.5, §12.8, req 25

> **Scope note.**
> 1. **Templates ship as built-in Python constants, not as pack JSON files.** They are
>    declarative `ReportTemplate` documents with the same validation discipline as a
>    ProcessDefinition — a pack author writing one is writing data, not code (rule 10) —
>    but no `packs/*/reports/` loader exists yet. All three built-ins (recap, log,
>    decision summary) are domain-neutral and say nothing a pack would need to override;
>    the loader belongs with the first template that does.
> 2. **No report UI.** The endpoints are real and tested; nothing renders them. G4.11 owns
>    rendering and is the natural place for the surface that displays a report.
> 3. **`redactions` counts hidden *prose*, not hidden facts.** A fact outside the viewer's
>    scope never enters the frame and is not counted, because counting it would itself
>    disclose that something exists in a compartment they cannot see — the count would be a
>    side channel. The stub reports the difference between total and visible messages,
>    which is arithmetic rather than an estimate.

## Goal
Reports as first-class objects generated by a worker: `ReportTemplate` (pack content)
map-reduces over session events into a narrative — with **structured facts injected from
records, never summarised from prose**, and the input stream filtered by the target
principal's visibility **before** the model sees it. A player recap is generated from a
context that never contained the villain's secret; never present beats scrubbed after.

## Subtasks
- [x] `ReportTemplate` model (pack content): `key` (campaign_recap | session_log |
      decision_summary | …), **`audience_mode` ∈ participant | overseer | sanitised**,
      `pipeline: [Step]`, `output_formats`.
- [x] `report` table (§12.8): `session_id`, `template_key`, `audience_mode`,
      `generated_for_principal_id`, `source_event_range`, `source_manifest_ids`
      (provenance), `content_md`, `redactions` JSONB, `artifacts`, review fields; RLS +
      isolation tests.
- [x] Pipeline executor (worker): chunk events by phase → summarise chunks (cheap model) →
      reduce to narrative (strong model) → render; all calls `purpose='report'` (egress
      policy applies — a local-only tenant reports on local models).
- [x] **Visibility-first input**: the event stream is filtered for
      `(generated_for_principal, audience_mode)` before any model call; redacted spans
      render as visible stubs ("[3 events not visible to you]") recorded in `redactions`.
- [x] **Record-injected facts**: resolutions, entity state changes, and disclosure events
      enter the pipeline as structured frames from their tables; the model narrates around
      them; a lying summary of a roll is structurally impossible in the fact frame (INV-7's
      spirit at report scale).
- [x] `decision_summary` template (enterprise/swdev): extracts `DisclosureDecision` +
      concession/`await` records into a structured decision log — the artefact no
      competitor produces (H5.10 builds on it).

## Acceptance criteria
- A participant recap generated over a session containing concealed secrets contains no
  trace of them — `tests/leak/` scan of the report artifact, same method as G4.7.
  → `test_participant_report_contains_no_unheld_secret_content`
- A planted prose lie about a roll result cannot reach the report's fact frame — the
  rendered report states the recorded value.
  → `test_report_facts_come_from_records_not_prose`
- Redactions render as visible stubs and are enumerated in `report.redactions`.
  → `test_redactions_are_visible_stubs_not_silent_omissions`
- The report row's provenance (`source_event_range`, `source_manifest_ids`) is sufficient
  to regenerate an identical fact frame.
  → `test_report_provenance_regenerates_identical_fact_frame`
