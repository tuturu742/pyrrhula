# G4.15 — Repo-as-knowledge ingestion (D15, docs-first)

**Phase:** 4 · **Track:** S · **Est:** 5d · **Status:** done (partial — see scope note)
**Depends on:** A1.10, G4.6 (G4.12 for the MCP fetch path) · **Blocks:** G4.17
**Plan refs:** §14.5 (D15), §6.1, §16.6

> **Scope note.**
> 1. **Tarball only; the MCP git path is not wired.** The task itself offers the tarball as
>    the fallback that "decouples this task from G4.12 slippage and serves air-gapped
>    tenants", and both reasons still hold — G4.12's shipped transport is deliberately
>    unreachable (no MCP server in this environment), so a `get_tree`/`get_file` path would
>    be code with nothing to call. `ingest_repo_snapshot` takes `list[RepoFile]`, so adding
>    the MCP acquisition path is a new caller, not a change to the ingestion.
> 2. **Chunking is whole-file for documents too, not semantic yet.** The distinction the
>    task cares about — which entries were treated naively — is carried by
>    `RepoIngestReport.experimental`, which names every source-code path. Turning the
>    semantic chunker on for markdown is a change inside `_chunk_published` with no effect
>    on the mapping, the scans, or the version DAG.
> 3. **`purpose='embed'` metering is not written**, because nothing embeds yet: chunks land
>    with `embedding = NULL` and the existing `embed_chunks` job is what fills them (and
>    meters them) when a caller enqueues it. Metering an embedding that did not happen would
>    be a false cost row.
> 4. **The secret-pattern scan is posture, not INV-8**, and says so in
>    `core/knowledge/secret_patterns.py`'s own docstring: the assembler cannot exclude a
>    secret nobody registered, and a committed credential is exactly such a secret.

## Goal
A git repository enters Pyrrhula as **knowledge, not a filesystem**: a snapshot pinned to a
commit SHA is ingested through the existing A1.x pipeline into KnowledgeSources, with a
path-glob→class mapping and docs-first chunking. Pyrrhula holds no clone and no worktree
(D15's rejected list); the coding agent reads code natively — retrieval only needs to
*brief*.

## Subtasks
- [x] Snapshot acquisition, two paths: read-only MCP git tools (`get_tree`/`get_file`
      through G4.12's client, allowlisted) **or tarball upload** — the fallback decouples
      this task from G4.12 slippage and serves air-gapped tenants.
- [x] Version mapping: one `knowledge_source_version` per ingested SHA — the
      content-addressed version DAG (A1.1) maps naturally onto the commit DAG; re-ingesting
      a new SHA is a new version; unchanged files skip re-embedding via the existing
      content-hash check (A1.2).
- [x] Per-attachment **path-glob→class mapping** (workspace-configurable, shipped default):
      `docs/adr/**`, `CONTRIBUTING*`, `CLAUDE.md`, conventions → `rules`; `docs/**`,
      `README*`, `tasks/**` → `lore`; everything else → `misc`. The mapping is data on the
      attachment, not code.
- [x] **Docs-first chunking**: markdown/text files chunk through the existing semantic
      chunker; **source-code files ingest with plain chunking into `misc` and are flagged
      `experimental` on the chunk** — code-aware chunking (tree-sitter, symbol-level) is an
      explicit Phase-6 trigger row, not this task.
- [x] Security, both scans at ingestion: **G4.6's injection scanner** (a README is
      attacker-controlled text headed for a tool-calling agent's context — same quarantine
      flow); a **declarative secret-pattern scan** (gitleaks-style regex/entropy rules as
      config data, per rule 10 — no scanner plugins) that **quarantines** hits for overseer
      review.
- [x] Ingestion runs as a worker job; `purpose='embed'` metering as usual; the source
      records repo identity + SHA for provenance.

## Acceptance criteria
- Ingesting this repository at a SHA yields sources where `tasks/**` files are `lore` and
  `CLAUDE.md` is `rules`, retrievable through the standard cascade with scope pushdown.
  → `test_repo_snapshot_ingests_with_path_glob_class_mapping`
- Re-ingesting the same SHA is a content-hash no-op; a new SHA creates a new version whose
  diff shows only changed entries (A1.8 diff over repo versions).
  → `test_same_sha_is_noop_and_new_sha_versions_the_diff`
- A planted committed AWS-style key is quarantined by the secret-pattern scan — absent from
  retrieval until reviewed; the task's docs state plainly this is **posture, not INV-8**
  (the assembler cannot exclude a secret nobody registered).
  → `test_committed_credential_pattern_is_quarantined_from_retrieval`
- A planted "ignore previous instructions" line in a README is quarantined by the injection
  scan (G4.6 reuse).
  → `test_repo_readme_injection_content_is_quarantined`

## Design decisions
- **Docs-first is a scoping decision, justified**: (a) the A1.x pipeline already does
  markdown well; (b) the dogfood pilot's working set — `tasks/`, `docs/`, the plan — is
  entirely markdown; (c) code-aware chunking is a retrieval-research project with its own
  eval, and the delegated coding agent reads the code itself anyway. Deferring it is named
  in §15.9, not silent.
- **No clone in core, ever.** The moment core holds a worktree, someone will run something
  in it; D15's rejected list exists to keep rule 10 unambiguous.
