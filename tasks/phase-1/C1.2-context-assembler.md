# C1.2 — ContextAssembler ★★ (critical path)

**Phase:** 1 · **Track:** C · **Est:** 6d · **Status:** done
**Depends on:** A1.7, C1.1 · **Blocks:** C1.3, C1.4, E2.6, F3.6 — everything downstream calls this
**Plan refs:** §4.1, §6.3, INV-1/2/8. **The single most important module in the codebase.**

## Goal
The ONLY code path from stored text to model context. **Freeze the signature in week 1 of
Phase 1 even if the body is a stub:**
`assemble(viewer: Principal, phase: Phase, session, budget) -> ContextManifest` — no
defaults, no `Optional` (INV-2).

## Acceptance criteria
- `assemble()` without viewer or phase does not typecheck; runtime guard also raises.
  → `test_assemble_without_viewer_or_phase_does_not_typecheck` (signature inspection: no
    default on either param, so a real call site omitting them is a mypy error),
    `test_assemble_runtime_guard_raises_on_none` (explicit `TypeError` guard, for a call
    site that bypasses static typing with `# type: ignore`)
- Deterministic: same inputs (pinned versions, seeded trigger_pct) → byte-identical rendered
  context (feeds INV-10).
  → `test_assemble_is_deterministic_across_repeated_calls`
- Out-of-scope content absent under adversarial queries (negative test with planted
  "leak-bait" entries in a foreign scope).
  → `test_out_of_scope_leak_bait_never_appears_even_as_best_match`,
    `test_viewer_with_no_workspace_relationship_gets_no_knowledge`
- Budget property: rendered context ≤ `max_tokens`; per-class content ≤ bucket ± one chunk.
  → `test_rendered_knowledge_respects_bucket_budget_within_one_chunk`

## Design decisions
- **`assemble()`'s exact parameter set**, since the plan's pseudocode signature
  (`assemble(viewer, phase, session, budget)`) is illustrative, not literal Python:
  `viewer: Principal` and `phase: PhaseSpec` are the two frozen, defaultless positional
  parameters INV-2 requires; everything else is keyword-only and required
  (`tenant_id`/`workspace_id`/`session_id`/`query_text`/`query_embedding`) except genuine
  injection-seam hooks with sensible pass-through defaults (`entity_state_renderer`,
  `secrets_gate`, `reranker`, `cache`, `activated_entries_by_class` — matching this
  project's established "required unless it's an injectable seam" convention from Track
  B). `phase.budget` (already on `PhaseSpec` from B1.1) supplies the knowledge-cascade
  budget directly rather than a separate `budget` argument duplicating it; a distinct,
  required `history_max_tokens` covers the plan's separately-called-out "recent turns
  under their own token budget" subtask, since no such field exists anywhere in B1.1's
  `BudgetSpec`.
- **`phase.budget is None` (a pure-await phase, e.g. B1.1's own `feedback_loop` example)
  is handled gracefully, not rejected.** `PhaseSpec`'s own docstring says such phases
  "generate no agent turn and need no context budget" — nothing stops a caller from
  invoking `assemble()` on one anyway (e.g. to render just entity state + history for an
  await-phase UI), so it degrades to zero knowledge rather than crashing.
  `test_phase_with_no_budget_produces_no_knowledge_but_does_not_crash` proves this.
- **Empty scope sets short-circuit before retrieval**, not after: `search_and_budget`'s
  `search_dense`/`search_sparse` raise on an empty `scope_keys` (INV-4's "empty is
  indistinguishable from no filter" guard) -- a viewer with no legitimate scope access at
  all (`scopes_for` returns nothing) would trip that guard on every call otherwise, so
  `assemble()` checks `scope_set` truthiness itself and returns zero knowledge directly.
- **Citation ids (`k1`, `k2`, ...) are assigned by final render order**, not by chunk_id or
  entry_id -- short, sequential, and (because WRRF rank + bucket fill are themselves
  deterministic given a fixed corpus and `reranker=None`) exactly as stable as the
  rendered context itself. C1.8 (citation validation) will check cited ids against
  `ContextManifest.entries` by this same `citation_id` field.
- **Two new lookups added to `core.knowledge.repo`** (`get_source_names`,
  `get_entry_titles`) rather than raw SQL inside the assembler -- INV-1's whole point is
  that stored-content reads go through the repo layer; adding a small, real repo function
  is more in the spirit of the invariant than ad hoc `text()` queries duplicated in the
  assembler, and it's exactly the kind of read `repo.py`'s own docstring already
  anticipated ("the read the assembler will filter by scope_key/class and budget once it
  exists").
- **`BudgetedChunk` gained a `token_count` field** (A1.6, additive, one construction
  site) -- needed so the assembler can report real per-class token totals in the
  manifest without a second query; `fill_all_buckets`'s own `tokens_used` accounting
  isn't otherwise exposed through `search_and_budget`'s return type.
- **History/entity-state token accounting uses a word-count proxy**, not a real
  tokenizer -- consistent with the acceptance criterion's own "± one chunk" tolerance,
  and avoids pulling a live tokenizer dependency into the assembler for a budget-planning
  number that A1.2's ingestion-time `token_count` already answers precisely for knowledge
  chunks (the part that actually needs precision, since it drives bucket-fill cutoffs).
- **Entity state and the secrets gate are real injection seams, not documentation-only
  stubs** -- both are called unconditionally every `assemble()`, with defaults that are
  true no-ops (`test_default_seams_are_true_no_ops`) and a test proving a real
  implementation's output actually reaches `rendered_context`/`redactions`
  (`test_entity_state_and_secrets_gate_seams_flow_into_the_manifest`) -- so F3.6/E2.6 slot
  in later by passing a real callable, no signature change to `assemble()` itself.
