# C1.3 — ContextManifest + replay (INV-10)

**Phase:** 1 · **Track:** C · **Est:** 3d · **Status:** done
**Depends on:** C1.2 · **Blocks:** C1.8, D1.4, G4.10
**Plan refs:** §6.3 step 10, §12.7, INV-10

## Goal
The persisted record of exactly what a model saw and why — the substrate for citations, the
context inspector, replay, and forensic debugging.

## Subtasks
- [x] `context_manifest` table per §12.7 (append-only): viewer, phase, `entries[]` with
      `(source_id, version, entry_key, chunk_id, class, bucket, rank, score, why)`,
      `redactions`, `resolution_ids`, `entity_versions`, `behavior_profile_version`
      (nullable until Phase 2), `token_counts`, `rendered_hash`.
- [x] `why` values are structured enums (`keyed:sticky`, `dense:rank3`, `constant`, …), not
      free text — the inspector groups by them.
- [x] Messages reference their manifest (`message.context_manifest_id`).
- [x] **Replay test (INV-10), CI-blocking:** re-run `assemble()` from a stored manifest's
      inputs (pinned versions + resolution records + seeds) and assert
      `sha256(rendered) == rendered_hash`. Lives in `tests/replay/`.
- [x] Read API for the inspector (D1.4): manifest by message id, principal-checked (a
      participant may read manifests for contexts *they* were the viewer of; facilitator per
      permission).

## Acceptance criteria
- Replay green across a scripted 20-turn session, including sticky/cooldown activation state.
  → `tests/replay/test_context_manifest_replay.py::test_replay_across_a_scripted_20_turn_session_with_sticky_cooldown_state`
- Manifest access control: player A cannot read the facilitator's manifest (test).
  → `test_other_participant_cannot_read_someone_elses_manifest`,
    `test_facilitator_can_read_any_manifest_via_read_any_manifest_permission`
- No UPDATE/DELETE grants (append-only test).
  → `tests/isolation/test_append_only_grants.py` (`context_manifest` moved into
    `_APPEND_ONLY_TABLES_TODAY`)

## Design decisions
- **`why` values come straight from A1.6's own `BudgetedChunk.why`** (`"+".join(hit.contributing_lists)`
  e.g. `"dense+sparse"`, or `"constant"`) — already structured, not free text; no separate
  enum was needed since A1.6 had already solved this.
- **What "replay" verifies, precisely.** The plan's own §12.7 schema for `context_manifest`
  has no `query_text`/`query_embedding`/history column — only the *result* of assembly
  (entries, redactions, token_counts, `rendered_hash`). So replay isn't "reconstruct the
  inputs from the manifest and re-run retrieval from scratch" (the schema doesn't support
  that); it's the property INV-10 actually needs: **the same inputs that produced a
  manifest reproduce the same hash, reliably, across an evolving session** -- proven with a
  full 20-turn scripted session where sticky/cooldown keyword-activation state genuinely
  evolves turn to turn (real state most likely to expose a hidden nondeterminism -- unstable
  dict ordering, an unseeded RNG, wall-clock leakage), not a single static call.
- **`get_manifest_for_message` takes an injected `permission_service: PermissionService`**,
  not a hardcoded `RolePermissionService` import -- `core/` depends on the port, never
  constructs a specific adapter (CLAUDE.md rule 12); the composition root/caller decides
  which adapter, matching every other port injection in this codebase
  (`model_provider_factory`, etc.). Caught and fixed before it shipped, not after.
- **New `role_permission` action: `read_any_manifest`** (workspace-scoped, granted to
  `facilitator`/`overseer`), added by this migration rather than reusing the existing
  `view_workspace` action every workspace role already holds -- reusing it would let any
  participant/viewer read anyone else's manifest, defeating the access-control acceptance
  criterion.
- **`message.context_manifest_id`'s FK is completed here**, not left as the plain
  unenforced UUID column B1.7 added ("no context_manifest table yet"). `ondelete=SET NULL`:
  the table is append-only in practice (no UPDATE/DELETE grant) so this essentially never
  fires, but a message should never become permanently unreadable if it somehow did.
- **Not auto-wired into `core.agents.runtime`.** No task in Phase 1's list names "call
  `assemble()` as part of a real agent turn" as its own job, and that integration needs a
  real rule system + resolution service (C1.5/C1.6) to make sense for a real phase.
  `write_context_manifest`/`get_manifest_for_message` are complete, tested, standalone
  functions today -- matching this project's established injection-seam discipline.
