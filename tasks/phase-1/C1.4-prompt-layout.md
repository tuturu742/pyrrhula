# C1.4 — Prompt layout for caching

**Phase:** 1 · **Track:** C · **Est:** 3d · **Status:** done
**Depends on:** C1.2 · **Blocks:** —
**Plan refs:** §6.3 step 9, §16.1. In Phase 1 deliberately — this is a 5–10× cost lever
only if the layout is right from day one.

## Goal
Order context stable → volatile so provider prompt caching (and local KV-cache prefix reuse)
hits on the 60–80% stable prefix every turn.

## Subtasks
- [x] Layout contract: system + persona + entity schema + constant knowledge + rule system
      (stable across a session) strictly **before** retrieved chunks + recent turns
      (volatile). One volatile token near the top invalidates the whole prefix — enforce
      ordering structurally (typed sections, not string concat).
- [x] Stable-section rendering must be deterministic and byte-stable across turns of the
      same session (no timestamps, no dict-order drift) — snapshot test.
- [x] Provider cache markers where supported (via `ModelProvider` capabilities — e.g.
      Anthropic cache_control) applied at the stable/volatile boundary.
- [x] `usage_record.cached_tokens` populated from provider responses; **cache-hit-rate
      metric** exported per session (Q7 telemetry starts here).
- [x] Rough cost dashboard data endpoint (tokens + estimated spend per session/workspace) —
      §16.1 says build the rough one in Phase 1, not Phase 5.

## Acceptance criteria
- Two consecutive turns in one session share a byte-identical stable prefix (test).
  → `test_two_consecutive_turns_share_a_byte_identical_stable_prefix`
- Cache-hit rate visible per session via API; non-zero against a caching provider in a live
  smoke test (manual, documented).
  → `GET /sessions/{id}/usage` and `GET /workspaces/{id}/usage`
    (`packages/api/routes/usage.py`, tested end to end in `test_usage_flow.py`). **The live
    smoke test against a real caching provider was not run** — no Ollama/Anthropic
    credentials are available in this sandbox, the same honest gap already flagged for
    B1.7's tool-calling code and this task's own LiteLLM `cache_control`/`cached_tokens`
    plumbing (see design decisions). Documented here rather than silently assumed correct;
    someone with provider credentials should run one session against Claude and confirm
    `cached_tokens > 0` on the second turn before relying on this in production.

## Design decisions
- **`LayoutSections` (new: `core/assembler/layout.py`) makes the ordering structural**,
  not string-concatenation order that a future edit could quietly get backwards — a
  two-field frozen dataclass (`stable`, `volatile`) with `.stable_text`/`.volatile_text`/
  `.render()`. `ContextManifest` gained two fields, `stable_prefix`/`volatile_suffix`
  (`rendered_context` is still the same joined text, kept for backward compatibility with
  C1.2/C1.3's existing consumers).
- **What's stable vs volatile, concretely, given what actually exists in Phase 1:**
  entity state (always stable -- the MVP renderer is a no-op today, F3.6's real one won't
  change every turn either) and constant-`why` knowledge entries (A1.5's `constant: true`,
  which fire regardless of query) are stable; ranked/retrieved (non-constant) knowledge and
  recent history are volatile. "System + persona + rule system" from the plan's wording
  have no concrete source yet in Phase 1 (no agent persona field, no RuleSystem until
  C1.5) -- nothing to add to the stable section for those until those tasks exist; the
  *shape* (a `stable` tuple slot) is ready for them.
- **The secrets gate runs once per layout side (stable knowledge, volatile knowledge)**,
  not once on the whole concatenated block -- otherwise redacting content would collapse
  the structural stable/volatile split right back into one string. This is a real,
  observable behavioural change from C1.2's original implementation (two hook
  invocations instead of one); `test_context_assembler.py`'s existing seam test was
  updated to a more realistic fake gate (only reports a redaction on the side that
  actually matched) rather than an unconditional one, since calling the old fake twice
  would have double-counted its hardcoded `Redaction`.
- **`GenerationRequest.cache_boundary_index`/`Chunk.cached_tokens`** (new port fields,
  both default to inert values -- `None`/`0` -- so every existing caller is unaffected).
  The LiteLLM adapter applies Anthropic's `cache_control: {"type": "ephemeral"}` marker at
  the boundary message only when `capabilities(model).supports_prompt_caching`, and
  extracts `cached_tokens` best-effort from either OpenAI's
  (`usage.prompt_tokens_details.cached_tokens`) or Anthropic's
  (`usage.cache_read_input_tokens`) shape, defaulting to 0 if neither is present.
  **Not exercised against a live provider** -- same honest flag as B1.7's tool-calling
  code; `test_provider.py`'s new tests mock `litellm.acompletion` directly.
- **`run_agent_turn` gained `cache_boundary_index: int | None = None`.** A single fixed
  index is valid across the whole tool loop, since tool-loop iterations only ever *append*
  to `conversation` -- the stable prefix's position never shifts. Not yet auto-computed
  from a real `ContextManifest.stable_prefix` (that wiring is the same "not yet integrated
  into the runtime" gap C1.2/C1.3 already flagged -- `assemble()` isn't called from
  `run_agent_turn` yet).
- **Rough cost dashboard**: `core.audit.usage_dashboard` (pure aggregation over
  `usage_record`, no new table) + two read endpoints,
  `GET /sessions/{id}/usage`/`GET /workspaces/{id}/usage`, both tenant-scoped through the
  existing `RequestContext`/`get_request_context` dependency chain (proven by
  `test_route_inventory.py`'s existing "every route needs a resolved principal" guard,
  which the new router satisfies the same way every other router does).
