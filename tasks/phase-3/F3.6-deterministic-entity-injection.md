# F3.6 — Deterministic entity injection

**Phase:** 3 · **Track:** F · **Est:** 3d · **Status:** done
**Depends on:** F3.5, C1.2 · **Blocks:** —
**Plan refs:** §6.3 step 7, §3.4, §12.7

## Goal
Assembler step 7 reads real entities: the viewer-visible slice of entity state is injected
into context **deterministically — never retrieved**. State is not knowledge (§3.4's
lesson): a character's current HP must be in context because it is current, not because it
scored well against the query.

## Subtasks
- [x] Replace the Phase-1 hardcoded minimal schema path in
      `core/assembler/context_assembler.py` step 7 with schema-driven injection: every
      entity in the workspace whose `scope_key` is in the viewer's `VisibilityResolver`-
      resolved scope set (reusing `scopes_for`, not a parallel implementation) — per-field
      `private` tags respected (a field the viewer can't see is absent, not blanked).
- [x] Rendering: compact, stable serialization of fields + FSM states + derived values
      (sorted-key order) — layout-stable so C1.4's cache prefix survives turns where state
      didn't change.
- [x] `ContextManifest.entity_versions` records exactly which entity versions were
      injected; `checkpoint.entity_versions` now real too (every entity in the workspace
      pinned, mirroring `knowledge_version_pins`'s identical "everything, not a viewer's
      subset" shape); INV-10 replay covers a turn with injected entities, including a
      second turn after a real mutation (F3.5) changes the rendered hash while each
      turn's own manifest still replays byte-identical.
- [x] Never-retrieved enforced structurally: entity injection is its own assembler step,
      called after `search_and_budget` and never passed through WRRF fusion/bucket fill —
      proven, not just asserted, by a fixture with zero knowledge sources at all where the
      entity's marker text still reaches `rendered_context` while `manifest.entries == ()`.

> **Scope note.** "Entities relevant to the phase (actors, declared subjects)" resolves
> to "every entity visible to the viewer's scope set" rather than a separate
> actor/subject-declaration mechanism — no such tracking exists anywhere in this phase's
> task list (process/session participant-entity linkage isn't a Phase 3 task), and
> visibility is the correctness-bearing gate regardless. Derived fields carry no
> tags/scope_key in F3.1's model, so they're always rendered (computed from the full,
> unfiltered entity data — a real limitation, documented in `injection.py`, additive to
> close later). `core.entities.injection.render_entity_state` is not wired as
> `context_assembler.py`'s *default* `entity_state_renderer` (would create a module
> cycle, since `injection.py` already depends on `context_assembler.py` for
> `EntityStateBlock`'s shape) — a caller passes it explicitly, the same "seam type
> defined here, real implementation wired at the composition root" pattern every other
> injection seam in this module already uses.
>
> **2026-09-15:** the parenthetical here used to add "no live turn loop calls
> `assemble()` yet in any case", which stopped being true and took the conclusion with
> it: every live turn calls `assemble()` (`core/process/live_session.py`) and passed no
> `entity_state_renderer`, so entity state reached no turn's context at all. The actor
> fields half is fixed; wiring a real `entity_state_renderer` at that call site is the
> remaining half.

## Acceptance criteria
- An entity field tagged `private` with a GM-only scope is absent from a participant
  viewer's context and present for the facilitator-configured viewer — same turn, two
  assemblies.
  → `test_private_field_absent_for_participant_present_for_authorized_viewer`
- Entity text never appears in retrieval candidates or bucket fills (instrumented assembly
  proves injection is post-budget).
  → `test_entity_state_is_injected_not_retrieved`
- A turn with injected entities replays byte-identical from manifest + pinned entity
  versions (INV-10).
  → `test_entity_injection_replays_identically_from_pinned_versions`
