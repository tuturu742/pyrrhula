# F3.7 — RPG pack

**Phase:** 3 · **Track:** F · **Est:** 10d · **Status:** done (partial — see scope note)
**Depends on:** F3.4, C1.5, A1.10 · **Blocks:** F3.9
**Plan refs:** §10.4, §15.6, §16.8 (SRD licensing), req 18

## Goal
RPG concepts delivered as a first-party pack on the generic framework — not hardcoded
(req 18). Attributes, skills, classes, spells, health FSMs and XP curves as EntitySchemas;
three RuleSystems; dice/stat tools; process templates; the `rpg_v1` overlay; SRD 5.1 seed
content into the library tenant. `packs/rpg/` imports nothing from `packages/core/`
(rule 9).

## Subtasks
- [x] `packs/rpg/schemas/`: character schema (attributes tagged
      `[attribute, modifier_source]` with a per-attribute `modifier_formula`;
      `hit_points [resource]` with `max_ref`/`low_threshold`; conditions
      `[status_set]`; `xp [progression]` with `curve_ref`); health FSM
      (healthy→bloodied→unconscious→dead, plus recovery transitions); spell/class/skill
      schemas.
- [x] `packs/rpg/rule_systems/`: `dnd5e_srd` (d20 grammar, modifier resolvers as CEL over
      entity fields), `pbta` (`2d6+stat → 10+/7-9/6-`), `coin_flip` — all three expressible
      via C1.5's `RuleSystem` with zero core changes (the §14.2 test, made real).
- [x] `packs/rpg/tools/` + `packs/rpg/processes/` + `packs/rpg/axes/` (the §8.2 axis pack,
      loading through E2.3) + `overlay/rpg_v1.json` (D1.6's shipped labels become
      pack-owned, merged into the existing system overlay via migration).
- [x] `packs/rpg/seed/`: seed content into the **library tenant** (A1.10/D13) — embedded
      once, forked-on-edit per tenant, real ingestion mechanism proven with real content.
      **Not actual SRD 5.1 text — see scope note.**
- [x] Pack loader (`core.packs.loader`, new, generic — reused unmodified by F3.8/F3.13):
      schemas validate (F3.1/F3.4), axes validate (E2.3), overlay resolves, seed ingests
      to the library tenant idempotently.

> **Scope note.** `hit_points [resource, vital]` in this task's own original text
> predates F3.4's closed 9-tag vocabulary decision — `"vital"` isn't one of the nine
> tags, so `hit_points` carries `[resource]` only (the closed set is the authoritative,
> later decision). **SRD 5.1 content and its CC-BY-4.0 legal review are not done here**:
> this environment cannot perform a legal review, and fabricating a claimed license
> attribution for text nobody checked would be worse than leaving the gap visible. What
> ships in `packs/rpg/seed/core_mechanics.json` is a small amount of originally-written,
> generic rules-summary text (uncopyrightable game-mechanics facts, not SRD expression)
> that proves the seeding *mechanism* — real library-tenant ingestion, real fork-on-edit
> — without any unchecked license claim. `packs/rpg/seed/ATTRIBUTION.md` names exactly
> what a human needs to do before this pack ships for real. Vocabulary-overlay writes to
> a system (`tenant_id IS NULL`) row can only happen at migration time — RLS's own
> `WITH CHECK` blocks the app role from ever writing one at runtime (by design, per the
> D1.6 migration's own docstring) — so `core.packs.loader` never touches
> `vocabulary_overlay`; a migration merges the pack's own `overlay/rpg_v1.json` content
> into the existing system row instead.

## Acceptance criteria
- "Create character" from the pack opens a populated sheet rendered by F3.10's generic
  widgets — no field builder, no empty schema (the phase-gate wording: the generic layer is
  below the floor of the median user's experience).
  → `test_create_character_yields_populated_sheet_from_pack_templates`
- All three rule systems resolve a request through C1.6's unchanged `ResolutionService`
  (d20 with a real modifier from entity state, PbtA band result, coin flip).
  → `test_three_rule_systems_resolve_through_unchanged_core`
- The pack contains no `import` from `packages/core/` — the packs-independence lint stays
  green with the pack fully populated.
  → `test_rpg_pack_has_zero_core_imports`
- SRD seed lands in the library tenant only; tenant B reads it, tenant B cannot write it,
  editing forks into tenant B (A1.10's mechanism, exercised with real content).
  → `test_srd_seed_is_library_read_only_with_fork_on_edit`

## Design decisions
- **The pack is the proof that the floor holds.** If making the sheet feel native requires
  a core change, F3.4's tag vocabulary or F3.1's schema subset is wrong — raise it (rule 9);
  the whole point of building the RPG experience as a pack is to find those gaps before
  INV-9 certifies genericity.
