## Acceptance criteria
- [x] Login → workspace list → open the T0.8 stub session and watch tokens stream. Verified
  with a scripted headless-Chromium (Playwright) run against `pnpm dev` proxied to a live
  containerized backend: register → `/` (workspace list) → workspace detail (agent list) →
  "Start Session" → session view → submit a message → SSE delivers the durable `message`
  events and the page renders both the user's message and the echoed assistant reply, with
  zero browser console errors.
- [x] `pnpm build` + typecheck green in CI; generated API types are the only response types
  used. `pnpm run lint`, `pnpm run typecheck`, and `pnpm run build` are all clean locally;
  added a `web` job to `.github/workflows/ci.yml` (pnpm install --frozen-lockfile → lint →
  typecheck → build) and made the final `build` job depend on it.
- [x] All user-facing core nouns already route through `label()` (grep-able rule). Verified:
  grepping `web/src` for the RPG-overlay display strings (`Arbiter`, `Rulebook`, `World /
  Campaign`, etc.) outside of `lib/vocabulary/labels.ts` returns nothing.

## Bugs found and fixed along the way
- Wrote `lib/api-client/client.ts` (imports `openapi-fetch`) and `vite.config.ts` (imports
  `node:path`, uses `__dirname`) before the corresponding dependencies
  (`openapi-fetch`, `@types/node`) were in `package.json` — both were straightforward
  `pnpm add` fixes once `tsc -b` surfaced them.
- `test_workspaces_are_tenant_isolated` (added alongside the new read-only
  `GET /workspaces` and `GET /workspaces/{workspace_id}/agents` endpoints) initially
  compared workspace `key` across two tenants, which legitimately collide — every tenant
  seeded via `seed_dev_tenant()` gets a workspace with `key="default"`. Isolation was never
  actually broken; the test was checking the wrong field. Fixed to compare `id` sets.
- A trailing `// eslint-disable-next-line no-console` in `lib/vocabulary/labels.ts` was
  flagged by `pnpm run lint` as an unused directive — this project's ESLint config never
  enabled `no-console`, so the disable comment was dead weight. Removed.
- Environment-only finding, not a code bug: a bare backgrounded `uv run uvicorn` process
  became unreachable from subsequent, separate shell-tool invocations in this sandbox even
  though the process was confirmed alive — worked around throughout by using the
  podman-compose stack (`docker/compose.selfhost.yml`) for all live-server verification
  instead, which stayed reliably reachable across calls.
- Live-browser verification needed a headless browser, which wasn't preinstalled; installed
  Playwright's Chromium build directly (`npx playwright install chromium`, skipping
  `--with-deps` since that path needs interactive `sudo` and wasn't available headlessly).
  `web/vite.config.ts`'s dev proxy target (`localhost:8000`) assumes a locally-run
  `uv run uvicorn`, which is the correct convention for real dev use, but this sandbox's
  loopback port 8000 is already bound (IPv6-only) by an unrelated local application and the
  podman stack for this session was published on 8010; temporarily repointed the proxy at
  `127.0.0.1:8010` to run the scripted browser flow, then reverted the config file (no diff
  left in `vite.config.ts`) before committing — the checked-in convention targets 8000 as
  intended.
- Also added, as part of making the acceptance criteria checkable rather than added scope:
  `GET /workspaces` and `GET /workspaces/{workspace_id}/agents` (`packages/api/routes/
  workspaces.py`) — read-only, tenant-scoped via `get_db_session`, with no prior Phase-0
  task having exposed a way to list a tenant's own workspaces/agents over HTTP.
