## Goal
Monorepo per plan Appendix B, one Docker image with selectable entrypoint, compose stack,
and CI running lint/type/test/build from the first commit.

## Subtasks
- [x] Monorepo layout: `packages/{core,adapters,api,worker,eval}`, `packs/{rpg,enterprise}`,
      `web/`, `migrations/`, `tests/{isolation,architecture,replay,leak,packs}`, `docker/`.
      Placeholder `__init__.py`/README stubs so the structure is real from day one.
- [x] Python tooling: `uv` (or `pip-tools`) lockfile, `ruff`, `mypy --strict` config scoped to
      `packages/`, `pytest` with async support.
- [x] Single `docker/Dockerfile` (multi-stage) whose entrypoint selects `api | worker | migrate`
      via command; build once, run three ways.
- [x] `docker/compose.selfhost.yml`: `pyrrhula` (api), `worker`, `postgres`
      (`pgvector/pgvector:pg16`), `redis:7`; optional `ollama` service commented in.
- [x] GitHub Actions: lint → typecheck → test → image build; jobs for the CI-blocking suites
      wired even while empty (they must fail loudly if their directories vanish).
- [x] OpenTelemetry wiring: tracer/exporter config in `core`, OTLP env-driven, no-op default.
- [x] `web/` scaffold reserved (created for real in T0.9); root README pointers.

## Acceptance criteria
- `docker compose -f docker/compose.selfhost.yml up` brings up api (health endpoint 200),
  worker (idle loop), postgres, redis, from the single image.
- CI is green on the scaffold and red if lint/type/test fails.
- The same image runs `migrate` as a one-shot command (no migrations yet → no-op success).
