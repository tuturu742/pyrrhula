# T0.4 — Isolation negative-test suite ★

**Phase:** 0 · **Track:** Infra · **Est:** 4d · **Status:** done
**Depends on:** T0.2 · **Blocks:** A1.10; gates every later schema change
**Plan refs:** §15.3, §12.1, §16.5, D13. **CI-BLOCKING. Never defer (governance note §15.3).**

## Goal
The test suite that *proves* multi-tenancy, rather than the RLS policy that claims it.
"T0.4 is the deliverable, not the RLS policy."

## Subtasks
- [x] Fixture: two tenants (A, B), each with representative rows in every currently-existing
      tenant-scoped table (`tests/isolation/conftest.py::two_tenants`,
      `test_filter_omission_matrix.py`). Library tenant deferred — see note below.
- [x] Cross-tenant read attempts on every tenant-scoped table via the normal repo layer
      (`test_tenant_scope_smoke.py::test_cross_tenant_read_returns_zero_rows`).
- [x] **Filter-omission tests:** raw SQL queries with no `WHERE tenant_id = ...` clause at all,
      scoped via `tenant_scope(A)`, asserting zero tenant-B rows — `test_tenant_scope_smoke.py`
      (principal, workspace) + `test_filter_omission_matrix.py` (identity, membership,
      workspace_membership, vector_store_item).
- [x] **Pooler-leak test:** `test_pooler_leak.py` — dedicated `pool_size=1` engine forces the
      second `engine.connect()` to reuse the exact physical connection from the first; asserts
      `app.tenant_id` did not survive across the reuse.
- [x] **Library-tenant matrix (D13):** deferred until the library tenant existed, then
      landed with A1.10 — `tests/isolation/test_library_matrix.py` ("this is that matrix,
      landed now that the library tenant exists") plus `test_library_rls_policy.py`. The
      box simply went unticked.
- [x] Table-coverage guard: `test_rls_catalog.py` (catalog-based: every `tenant_id`-bearing
      table has FORCE RLS, except the one documented exception, `job`) +
      `test_coverage_guard.py` (every RLS-covered table has an explicit filter-omission test).
- [x] Wired as a required CI job since T0.1 (`isolation` in `.github/workflows/ci.yml`); now
      also exercised for real (not just skip-on-no-DB) by the main `test` job.

## Acceptance criteria
- [x] Suite fails if any RLS policy is dropped, weakened, or a new tenant-scoped table ships
  without one — demonstrated live: created a scratch table with no RLS
  (`test_rls_catalog.py` failed), added RLS but no test coverage
  (`test_coverage_guard.py` failed), then removed the scratch table and confirmed green.
- [x] Filter-omission tests return zero foreign rows on every currently-existing table.
- [x] Coverage guard catches an intentionally added uncovered table (demonstrated live, see
  above).

## Deviation from the original subtask list
The library-tenant matrix is real Phase-1 work (D13/A1.10), not something Phase 0 can test
against — there's no library tenant yet. Everything else in this file's original subtask
list is implemented and passing against a live Postgres.

## Files / modules
`tests/isolation/` (+ shared fixtures in `tests/conftest.py`).

## Constraints
- One named foreign-tenant exception (library). A second exception of any kind must fail
  this suite until explicitly modelled and matrix-tested.
