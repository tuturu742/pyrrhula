# T0.7 — Audit + idempotency primitives

**Phase:** 0 · **Track:** Infra · **Est:** 4d · **Status:** done
**Depends on:** T0.2 · **Blocks:** E2.10, H5.4; used by every side-effecting service
**Plan refs:** §7.4, §5.6, §12.8, INV-5/6

## Goal
The append-only, hash-chained audit log and the idempotency machinery that makes
resume-from-checkpoint safe. Both are Phase-0 because retrofitting either touches every call
site — and you cannot retroactively audit what you didn't log.

## Subtasks
- [x] `audit_log` migration: append-only; app role gets `SELECT, INSERT` only (**no UPDATE,
      no DELETE — as grants, not convention**); fields per §12.8 incl. `prev_hash`, `row_hash`.
      RLS FORCE too (tenant-scoped like everything else, on top of the grant restriction).
- [x] `AuditService.append(...)` computing `row_hash = sha256(prev_hash || canonical(row))`;
      per-tenant chain head, serialised via `pg_advisory_xact_lock` so two concurrent appends
      for the same tenant can't both read the same `prev_hash`.
- [x] Chain verifier (`core.audit.verify.verify_chain`): walks a tenant's chain, checks both
      per-row hash consistency and prev/row linkage, returns broken row ids. The *worker job*
      that runs this nightly and pages someone is left as a hook — that's job/scheduling
      infrastructure, not the verifier logic itself.
- [x] `completed_operation` table + `@idempotent(key_fn)` decorator. **Claim-before-execute**,
      not cache-after: an atomic `INSERT ... ON CONFLICT DO NOTHING` claims the key before the
      wrapped function runs; concurrent losers poll the row until it reaches a terminal status
      instead of re-running the side effect.
- [x] Canonical JSON serializer (`core.audit.canonical.canonical_json`): stable key order,
      compact separators, and *rejects* floats outright (hash-instability source) rather than
      silently normalising one.

## Acceptance criteria
- [x] `UPDATE audit_log ...` as the app role fails with a permission error — test
      (`test_app_role_cannot_update_or_delete_audit_log`), plus a live grant-table check.
- [x] Tampering with a row (via the admin/migrator role, since the app role structurally
      cannot) is detected by the verifier — test (`test_verify_chain_detects_tampering`).
- [x] An `@idempotent` operation invoked twice with the same key executes side effects exactly
  once and returns identical results, including under 10-way concurrent invocation
  (`test_concurrent_calls_execute_side_effect_exactly_once`).
