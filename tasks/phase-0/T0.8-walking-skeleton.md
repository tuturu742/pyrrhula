# T0.8 — Walking skeleton

**Phase:** 0 · **Track:** Infra · **Est:** 5d · **Status:** done
**Depends on:** T0.3, T0.6 · **Blocks:** Phase 0 exit; H5.8 (usage data starts here)
**Plan refs:** §15.3, §12.8

## Goal
Prove the pipe end to end before any real feature exists: a hardcoded 2-phase process, one
agent, one model call through the port, tokens streaming over SSE, usage metered
in-transaction.

## Subtasks
- [x] Hardcoded 2-phase process (`prompt → respond`) in `core.process.skeleton` — a module
      docstring marks it explicitly deletable/replaceable by B1.1-B1.6's real interpreter.
      Does not import `api` or a concrete `adapters.*` class (ports-and-adapters dependency
      rule): the model-provider adapter and the Redis publish callbacks are both injected by
      the caller (`api/routes/sessions.py`, the composition root), not hardcoded in core.
- [x] `model_profile`, `agent`, `session`, `session_event`, `message`, `usage_record`,
      `price_table` (forward-compatible subset of §12.4/§12.7/§12.8; RLS FORCE on all but
      `price_table`, which is global pricing data like `role_permission`). B1.4/B1.7 extend
      this schema in place, not replace it.
- [x] One agent (`core.agents.seed.seed_dev_agent`, a dev/test helper — full agent CRUD is
      D1.5, Phase 1) with a `model_profile`; calls through the `ModelProvider` port. **Two
      provider options**, both real: `echo` (deterministic word-chunked echo, for tests and
      demos without Ollama/API keys) and any real LiteLLM provider (Ollama, OpenAI,
      Anthropic, ...) by setting `model_profile.provider`/`.model`.
- [x] SSE endpoint (`api/streaming/sse.py` + `pubsub.py`): Redis pub/sub fan-out on
      `session:{id}`, two message shapes on one channel — ephemeral `chunk` (live token
      deltas) and durable `event` (mirrors a `session_event` row). `Last-Event-ID` resume
      replays durable events from the database before subscribing live.
- [x] `usage_record` written in the same transaction as the assistant `message` and its
      `session_event`, with `purpose='generation'`, real token counts (via
      `ModelProvider.count_tokens`), and estimated cost from the seeded `price_table`
      (`ollama`/`echo`/wildcard rows, all $0 for v1 — honest, not fabricated pricing).
- [x] Live HTTP demonstration via `curl` against the running container (see below) — a
      dedicated stub UI page was judged redundant given curl already demonstrates the full
      register → session → message → live-SSE-stream flow end to end; T0.9 builds the real
      UI.
- [x] OTel spans in `submit_user_message` and `generate_agent_response`
      (`skeleton.submit_user_message`, `skeleton.generate_agent_response`, with
      provider/model attributes), composing with FastAPI's existing auto-instrumentation
      for the request-level span.

## Acceptance criteria
- [x] **Phase 0 exit:** a message round-trips through the 2-phase process for one tenant —
  `test_full_round_trip_writes_message_event_and_usage` (engine-level) and
  `test_full_http_round_trip_produces_assistant_reply` (HTTP-level), plus a live curl
  demonstration against the running container. A second tenant cannot see the session —
  `test_second_tenant_cannot_see_first_tenants_session`,
  `test_second_tenant_cannot_reach_first_tenants_session_via_api`, and full T0.4 filter-
  omission coverage for all six new tables in
  `tests/isolation/test_walking_skeleton_filter_omission.py`.
- [x] Reconnecting with `Last-Event-ID` replays missed durable events —
  `test_reconnect_with_last_event_id_replays_missed_events`, plus verified live: submitted
  a message, watched the full live SSE stream (chunks + both message events), then
  reconnected with `Last-Event-ID: 0` and confirmed only the assistant's message (event 1)
  replayed, not the chunks (which are correctly ephemeral/non-resumable by design) or the
  already-seen user message (event 0).
- [x] The message insert and its `usage_record` commit or roll back together —
  `test_partial_write_rolls_back_entirely`: injects a NOT-NULL violation on the
  `usage_record` insert partway through the same transaction as the message/event inserts
  and confirms **none** of the three rows survive, not just that the two that did survive
  are consistent.

## Bugs found and fixed along the way
- **`core.process.skeleton` initially imported `api.streaming.pubsub` directly** — a
  backward dependency (core must never depend on api). Fixed with `on_chunk`/`on_event`
  callback injection; the composition root (`api/routes/sessions.py`) wires the concrete
  Redis publishing behaviour.
- **Same violation for the `ModelProvider` adapter**: the engine was hardcoding
  `if provider_name == "echo": return EchoModelProvider()`, importing `adapters.*` from
  `core`. Fixed the same way — `model_provider_factory` is now a required parameter;
  `api/model_provider_factory.py` is the one place the concrete selection happens.
- **Foreign keys bypass RLS.** `create_session(workspace_id, agent_id)` originally trusted
  the FK constraints to prove the referenced rows belonged to the caller's tenant — they
  don't; Postgres FK checks run with elevated privileges that ignore RLS. A tenant-A caller
  could otherwise create a session referencing tenant B's real workspace/agent by id. Fixed
  with an explicit `tenant_scope`-filtered lookup before the insert; documented in
  `docs/agent-guide.md` §8 since this generalises to any future FK relationship.
- **Route handlers didn't translate the engine's `ValueError` (session/agent not found under
  RLS) into an HTTP error** — an unhandled 500 instead of a 404. Fixed in both
  `create_session_endpoint` and `submit_message_endpoint`; deliberately the same 404
  whether the referenced row is genuinely nonexistent or just belongs to another tenant, so
  the HTTP layer doesn't leak that distinction either.
- Migration housekeeping consistent with earlier phases: fixed a spurious autogenerate diff
  (declared `audit_log`'s index on the ORM model instead of leaving it raw-SQL-only) and a
  `sa.bulk_insert` date-literal bug (asyncpg needs a real `datetime.date`, not an ISO string).
- **`session_event` shipped without its append-only grant** (found in the Phase-0/1A
  review, not during T0.8). It's an append-only table (CLAUDE.md rule 5, plan `‡`), so the
  app role must have no UPDATE/DELETE grant — but this migration created it with the default
  full grants and never revoked them, unlike `audit_log` and `knowledge_source_version`.
  Fixed by a follow-up migration (`2d5a8c1f7e34_session_event_append_only`) plus a new
  catalog-based `tests/isolation/test_append_only_grants.py` that asserts the actual grants
  of every append-only table — the guard whose absence let this slip through in the first
  place. Latent (nothing ever updated `session_event`), but a hard-rule violation regardless.
