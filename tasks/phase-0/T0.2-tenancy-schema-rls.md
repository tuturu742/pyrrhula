## Goal
The tenancy/identity tables with row-level security enforced by the database, and the single
sanctioned way to open a DB session.

## Subtasks
- [x] Alembic baseline migration: `tenant` (with `isolation_mode`, `region`, `settings`),
      `principal` (kind: human|service|agent), `identity`, `membership`,
      `workspace_membership`, `role_permission`, `workspace`.
- [x] RLS on every tenant-scoped table: `ENABLE` + `FORCE ROW LEVEL SECURITY`; policy
      `tenant_id = current_setting('app.tenant_id', true)::uuid`.
- [x] `packages/core/tenancy/scope.py::tenant_scope(tenant_id)` async context manager —
      opens session, `SELECT set_config('app.tenant_id', $1, true)` (**transaction-local**),
      yields, commits/rolls back. Document that this is the ONLY session opener.
- [x] Dedicated non-superuser app DB role that does not own the tables (FORCE still applies,
      but belt and braces); migration role separate.
- [x] Seed helper for dev: create tenant + owner principal + workspace.
- [x] `role_permission` seeded with the v1 five-role matrix (owner/admin/editor/participant/
      viewer at tenant level; facilitator/participant/overseer/viewer at workspace level).

## Acceptance criteria
- A query through `tenant_scope(A)` cannot read tenant B's rows **even when the ORM WHERE is
  omitted** (proven properly in T0.4; a first smoke version lands here).
- Opening a session any other way is impossible without importing private internals — code
  review + a lint rule flag direct `sessionmaker` use outside `scope.py`.
- `set_config` uses `is_local=true`; a test borrows a pooled connection across transactions
  and asserts the GUC did not survive.
